# G60 / US demo Q&A card

**Use with build `77f0376`, the [runbook](bmw-demo-runbook.md), and the [claim ledger](bmw-demo-claim-ledger.md).** Answers are about the frozen prototype unless stated as pilot work. Keep each answer under 30 seconds and show the cited screen when useful.

| Likely question | Presenter answer and proof |
| --- | --- |
| What actually uses AI in this run? | “This frozen run is a deterministic reference analysis. The product has a configurable OpenAI analysis path, but we did not verify a live model or multi-agent run for this presentation. The proposed requirement, score and update shown here are reproducible from the saved inputs.” Show Pipeline/provider and the version actor `System:reference`. |
| How do you know the charging proposal is grounded? | “Its 264 links have exact workbook, sheet and row locations, and we manually checked 12 against the archived source. Those rows support separate public-charger search, availability, compatibility and positive experience signals. The combined in-car journey is our PM hypothesis. One linked phone-charging record is a false positive, so we make the PM review visible.” Show Evidence Trace and row 432, then the assumption label. |
| Why 80%? | “It is an explicit PM assumption for a future moderated trip-planning test. No supplied study establishes 80%. The responsible PM can revise it with a rationale.” Show Requirement → Measurable acceptance criteria. |
| How is 71.26 calculated, and why grade C? | “Version 2's five recorded factors run through the versioned `customer-priority-v1` weighted rubric. Some factors are heuristic or PM-assumed, so 71.26 is a priority judgment, not a measured preference. Grade C is separate because the selected feedback is undated, concentrated and contains conflicts.” Show Score. |
| Are the 4,365 rows representative of US drivers? | “No. They are imported evidence rows from selected G60 / US files. Source B contributes 2,626 of 3,610 unique feedback IDs, or 72.74%. We do not call that market prevalence.” Show Overview. |
| Can an agent approve? | “The API and database reject AI-labelled decisions; our API test returned 403. A self-declared `PM` actor was accepted in a disposable rehearsal, which proves only this prototype role check. BMW identity, SSO and permission mapping are pilot work. The live presenter makes any actual decision.” Show decision footer and audit only after the presenter acts. |
| What changes after new feedback? | “The next record is synthetic and undated. In our saved rehearsal, it added one linked evidence record and changed priority 71.26 to 71.33; the wording and 80% target stayed the same. One of 11 requirements reopened. The approved v2 stayed frozen while v3 awaited review.” Show Needs review → Versions. |
| What about other markets, competitor signals and scale? | “The data model and UI are scoped by vehicle and market, and the integrated platform work contains wider source and agent seams. We have not made a verified second-market claim in this frozen demo. A pilot would validate source permissions, market comparisons, volume, latency and review effort before promising scale.” Show G60 / US selector only as a scope control, not as evidence of a verified comparison. |
| Does BMW data go to public search or a model provider? | “This frozen reference run needs no live model call. The configurable analysis path would send selected input to its configured provider; BMW must approve data classification, model region and egress before a pilot. Public search queries must use public model/topic/market terms, never BMW verbatims.” |
| Is Codebeamer connected? | “No. This is an upstream requirements prototype. Exporting approved versions into BMW systems needs a jointly agreed interface, ownership and permissions.” |
| Where are cost, homologation and engineering details? | “BMW framed this challenge around market research and product planning. Detailed pricing, engineering specifications and homologation stay with their owners; the prototype can flag dependencies without pretending to decide them.” |
